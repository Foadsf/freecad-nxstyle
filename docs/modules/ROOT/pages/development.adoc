= Development
:description: How NX-Style is built: the launcher, the module, the ribbon files, shortcuts and the Strata embedding.

NX-Style changes nothing in FreeCAD.
It is a FreeCAD module that rebuilds the main window at start, plus a launcher that gives it a private profile.

== Repository layout

[cols="2,5",options="header"]
|===
| Path | Holds

| `launch_nx.py` | The launcher: finds FreeCAD, prepares the NX profile, starts FreeCAD with `-M NXStyle` (and Strata and Katydid), runs the test harnesses on a hidden desktop with a memory ceiling. Standard library only.
| `NXStyle/` | The FreeCAD module. `InitGui.py` hands over to `nxstyle.boot`.
| `NXStyle/nxstyle/resources/ribbons/` | The ribbons, as JSON.
| `NXStyle/nxstyle/resources/*.qss` | The NX light theme and the ribbon's stylesheet.
| `vendor/freecad-strata/` | Strata, as a git submodule.
| `vendor/Katydid/` | Katydid, as a git submodule.
| `tests/` | Launcher unit tests.
| `tools/` | `gen_docs.py` (the generated parts of these docs), `tutorial_table.py`, `iso10303_dictionary.py` (the EXPRESS dictionary from the ISO parts), `carbon_spec.py` (the Carbon API schemas the tests check against).
| `docs/` | This site's AsciiDoc sources (Antora), the replay results and the old Markdown notes.
|===

== Ribbon files

Each application has a JSON file; `apps.json` lists the applications and `common.json` holds tabs that several applications share.

[source,json]
----
{
  "title": "Modeling",
  "workbench": "PartDesignWorkbench",
  "tabs": [
    {"name": "Home", "groups": [
      {"name": "Feature", "items": [
        {"cmd": ["NXStyle_Extrude", "PartDesign_Pad"], "label": "Extrude", "size": "large"},
        {"dropdown": "Datum", "items": [
          {"cmd": "PartDesign_Plane", "label": "Datum Plane"}
        ]}
      ]}
    ]},
    {"include": "common:View"}
  ]
}
----

* `cmd` is a FreeCAD command name, or a list of candidates: the first that exists wins, so one file serves FreeCAD 1.0 and 1.1.
* `label` is the NX name on the button; `size` is `large` or `small`.
* `"optional": true` leaves the button out quietly when the command does not exist (Strata's commands, newer FreeCAD commands).
  Without it, a missing command is reported by the self-test.
* `{"include": "common:View"}` inserts a shared tab.
* A tab with `"contextual": true` (the Sketch tab in `sketch.json`) appears while it applies.
* `"essential"` (top level) lists the application's main commands, as names or lists of candidates. Their groups give up room last when the window is narrow, and the self-test checks that they stay reachable at every window size.
* A group's `"rank"` (a whole number, 0 by default, 10 for a group holding an essential command) sets the order in which groups give up room: lowest first.
* A group's `"step"` ties it to a guided workflow (`simulation.json`, checked by `fem_guide.py`).
* In `apps.json`, an application with `"ribbon": null` gets a ribbon generated from its workbench's toolbars. `"guide": "fem"` turns on the guided workflow.

How a page fits its width is decided by `ribbon_layout.py`, which uses neither Qt nor FreeCAD so that the unit tests can check it. `ribbon.py` measures the groups and applies the plan, and `layout_check.py` measures the result for the self-test.

== Theme colours

`theme.py` holds every colour of the NX theme as a token (`accent`, `chrome`, `tint` and so on).
The stylesheets write `@nx-<token>` in place of a colour, and `theme.stylesheet()` fills the tokens in when it loads them. An unknown token is an error.
Python code uses `theme.color("accent")`.
`tests/test_theme.py` fails if a stylesheet, or the shell, ribbon, finder or PLM module, contains a literal colour.

The xref:nx-to-freecad.adoc[] tables are generated from these files.

== Keyboard shortcuts

`shortcuts.TABLE` lists each key as an `Entry` with the NX command, the key, where it works and the FreeCAD command.
Section comments (`# ---- …`) group the table, and the xref:keyboard-shortcuts.adoc[] page follows those groups.
The self-test presses every key.

== Strata [[strata]]

`plm.py` hosts Strata through its embedding API (freecad-strata `1f71005` on):

[source,python]
----
import strata.boot as sb
from strata.ui import theme

sb.configure(host_toolbar=True, panel_area="left",
             shortcuts={"Strata_Compare": None, "Strata_Sync": None})
sb.on_ready(lambda: ribbon.add_actions(sb.actions().values()))   # plm.py then calls sb.activate_commands()
theme.set_overrides(light={"accent": "#00838F"})
----

* `host_toolbar=True`: Strata adds no toolbar or workbench of its own and never re-activates the workbench.
* `panel_area="left"`: the panel is made with the navigators.
* `actions()`: Strata's commands as QActions, enabled with the active project.
* `theme.set_overrides`: Strata's panels in NX-Style's colours.
* `shortcuts=` (freecad-strata `37db86f` on): Strata's own keys are Ctrl+Shift+H, V, D, R and Y. D and Y are NX's Drafting and Layout keys, so Compare and Sync get none; NX-Style's key pass would take D and Y back anyway, but Strata's Tools-menu entries would then show keys that do nothing.
* `activate_commands()`: in host mode Strata binds its keys only when this runs; `plm.py` calls it before NX-Style takes its keys back.

The submodule is pinned; update it with `git submodule update --remote vendor/freecad-strata` and commit the new pin after the self-test passes.

== Katydid [[katydid]]

Katydid is its own project and stays unmodified in `vendor/Katydid`; NX-Style adds no code to it.

* The launcher loads it with `-M`, like Strata (`find_katydid`): off with `--no-katydid` or `"algorithmic_modeling": "none"`, and not loaded twice when a Katydid sits in the NX profile's `Mod` folder.
* `apps.json` offers it as the *Algorithmic Modeling* application (`KatydidWorkbench`), with its ribbon in `algorithmic.json`.
* Katydid registers `Katydid_Canvas` and `Katydid_Bake` when FreeCAD starts (Katydid `a0a9e8a` on), so *Canvas* is also on the shared Tools tab (`common.json`, `"optional": true`). Starting Katydid's workbench opens the canvas, so the workbench is never preloaded; switching to the application starts it.
* The canvas is a floating `QDockWidget` named `KatydidDock`; NX-Style leaves it out of the navigator tab strip.

Update the pin the same way: `git submodule update --remote vendor/Katydid`, then the self-test.

== Carbon [[carbon]]

Carbon is a server, not an add-on, so it is not a submodule and the launcher loads nothing for it (`find_carbon` only reports how it is set up; `--no-carbon` sets `NXSTYLE_CARBON=0`, which leaves the commands unregistered).
It is AGPL-3.0 with commercial Enterprise files, so NX-Style copies none of it and talks to it over its HTTP API only (xref:manufacturing.adoc#_why_a_connection_not_a_bundled_copy[why]).

* `carbon.Client.call("items.createPart", {...})` is `POST <server>/api/v1/items/createPart` with the arguments as the body and the key as a bearer token; lists answer `{"results", "count"}`, refusals `{"code", "status", "message", "data": {"category"}}`. 429 and 503 are retried (`Retry-After`).
* `carbon.OPERATIONS` lists every operation used. `tests/data/carbon-openapi.json` holds their schemas, cut from Carbon's published OpenAPI document by `python tools/carbon_spec.py` (or from a server's own `/api/v1/openapi.json`); the stand-in server of the tests rejects any request those schemas reject.
* `carbon.Publisher` does the reads and either makes or lists the writes (`dry_run`), which is what *Review* shows.
* Uploads take two steps, as in Carbon's own browser upload: a signed URL from Carbon (`createModelUploadUrl`, `createItemDocumentUploadUrl`), a PUT of the bytes to it (without the API key), then for a model `insertModelUpload`.

When Carbon renames an operation, `tools/carbon_spec.py` says which; `tests/test_carbon.py` then fails until `carbon.py` follows.

== Rules the code keeps

* Never write to the normal FreeCAD profile: the launcher refuses any profile that overlaps it.
* Metric by default.
* Use FreeCAD's real commands; add an NX-Style command only where FreeCAD has none.
* No Siemens icons, text or assets.
