= Installation
:description: Install FreeCAD NX-Style, start it, update it and remove it.

FreeCAD NX-Style is a launcher and a FreeCAD module.
There are two ways to get it: a release bundle, which carries FreeCAD itself and needs nothing else, or the project folder from Git, which runs with a FreeCAD you already have.

[#bundle]
== Download a release bundle

Each https://github.com/Foadsf/freecad-nxstyle/releases[release] has one download per system: an official FreeCAD release, unmodified, with NX-Style, the add-ons it bundles and the launcher. Nothing is installed into the system and nothing is downloaded when it starts. Your normal FreeCAD, if you have one, is never touched.

[cols="2,2,4",options="header"]
|===
| System | Download | Start it

| Windows 10/11, Intel or AMD
| `NX-Style-<version>-windows-x86_64.zip`
| Unzip it anywhere you can write to, then double-click `NX-Style.exe`.

| Windows 11 on Arm
| `NX-Style-<version>-windows-arm64.zip`
| As above. FreeCAD 1.1.4 has no Arm build for Windows, so FreeCAD runs through Windows' built-in x64 emulation; only `NX-Style.exe` is native.

| Linux, Intel or AMD
| `NX-Style-<version>-linux-x86_64.AppImage`
| `chmod +x` the file, then run it. It needs FUSE (`fuse3` on current distributions) like any AppImage.

| Linux on 64-bit Arm
| `NX-Style-<version>-linux-aarch64.AppImage`
| As above.

| macOS, Apple silicon
| `NX-Style-<version>-macos-arm64.dmg`
| Open the disk image and drag NX-Style to Applications.

| macOS, Intel
| `NX-Style-<version>-macos-x86_64.dmg`
| As above.
|===

`SHA256SUMS.txt` on the release page lists the checksum of each download (`sha256sum -c SHA256SUMS.txt --ignore-missing` on Linux, `shasum -a 256` on macOS, `Get-FileHash` in PowerShell).

Every bundle runs the same launcher as the project folder, so every xref:#options[launcher option] works when you give it on the command line:

[cols="1,3",options="header"]
|===
| System | From a terminal

| Windows | `nxstyle.cmd --dry-run` in the unzipped folder (it waits and prints; `NX-Style.exe` is for double-clicking)
| Linux | `./NX-Style-<version>-linux-x86_64.AppImage --dry-run`
| macOS | `/Applications/NX-Style.app/Contents/MacOS/NX-Style --dry-run`
|===

`--headless-check` loads NX-Style and its add-ons in the bundled FreeCAD without a window and says whether all of it loads; the release workflow runs it, and the start-up steps of the xref:testing.adoc[self-test], on every bundle before a release.

First start of a downloaded bundle::
The bundles are not signed by Apple or Microsoft yet.
On macOS the first start is refused until you allow it in *System Settings › Privacy & Security › Open Anyway* (or run `xattr -dr com.apple.quarantine /Applications/NX-Style.app`).
On Windows, SmartScreen may ask: *More info › Run anyway*.

OpenGL without a GPU driver::
FreeCAD needs OpenGL 2 or newer, and no bundle carries a GPU maker's driver: each uses the system's.
In a virtual machine, over a remote desktop or without a working GPU driver, the Windows and Linux bundles notice and start FreeCAD on Mesa's software renderer instead (the first line they print says which). It is slower but works.
Set `NXSTYLE_SOFTWARE_GL=1` to force software rendering, `0` to forbid it.
On Linux the software renderer is the system's Mesa, which every desktop distribution has (Debian/Ubuntu: `libgl1-mesa-dri`, Fedora: `mesa-dri-drivers`).

To update a bundle, download the new one; the NX profile is kept (xref:#profile[]). To remove it, delete the folder, AppImage or app, and the NX profile if you want.

The rest of this page is about running NX-Style from the project folder with a FreeCAD you installed yourself.

[#source]
== Requirements

You need FreeCAD itself, the project folder, and Python to run the launcher.

[cols="1,3",options="header"]
|===
| Needed | Details

| FreeCAD 1.0 or newer
| Tested on Windows 11 with FreeCAD 1.0.2 (Qt 5.15) and 1.1.4 (Qt 6). Install it from https://www.freecad.org/downloads.php[freecad.org] or your package manager.

| Python 3.8 or newer
| Only to run the launcher; it uses the standard library only. FreeCAD's own Python works too.

| Git
| To get the project with its submodules, and for xref:data-management.adoc[Strata] (version history), which runs `git` behind the scenes. On Windows, https://git-scm.com/download/win[Git for Windows] puts `git.exe` on the PATH.
|===

NOTE: Linux is tested on Linux Mint 22.2 with the FreeCAD 1.1.4 AppImage: put the AppImage in a folder in your home directory, such as `~/Applications`, and the launcher finds it. macOS is supported by the launcher (it looks for FreeCAD in the usual places) but has not been tested yet.
The hidden-desktop test mode is Windows-only; on Linux the self-test runs on whatever `DISPLAY` it is given, for example an Xvfb display.

== Get the project

Clone it with its submodules: xref:data-management.adoc[Strata] in `vendor/freecad-strata`, xref:algorithmic-modeling.adoc[Katydid] in `vendor/Katydid`, FreeCAD's xref:sheet-metal.adoc[SheetMetal add-on] in `vendor/FreeCAD_SheetMetal`, xref:laser-cut.adoc[LCInterlocking] in `vendor/LCInterlocking` and the xref:dfm.adoc[DFM Workbench] in `vendor/FreeCAD-DFM-Workbench`.

[source,bash]
----
git clone --recursive https://github.com/Foadsf/freecad-nxstyle
----

If you cloned without `--recursive`, or downloaded a ZIP of the repository, fetch them separately:

[source,bash]
----
git submodule update --init
----

NX-Style still starts without them; the launcher then prints `Strata: not found`, `Katydid: not found`, `SheetMetal: not found`, `LCInterlocking: not found` or `DFM: not found` and how to get them.

The DFM Workbench also needs OCP (cadquery-ocp), which FreeCAD does not ship. Until it is installed, the launcher prints `DFM: off: it needs OCP` and starts without it. Install it once (about 165 MB from PyPI, with FreeCAD's own Python, into `FreeCAD-NXStyle/pydeps` beside the NX profiles):

[source,bash]
----
python launch_nx.py --install-dfm-deps
----

== Start it

From the project folder:

[source,bash]
----
python launch_nx.py
----

The launcher finds the newest FreeCAD on the machine, prepares the NX profile and starts FreeCAD with the NX-Style interface.
It prints what it used:

----
FreeCAD 1.1.4: C:\Users\you\AppData\Local\Programs\FreeCAD 1.1\bin\freecad.exe
NX profile: C:\Users\you\AppData\Local\FreeCAD-NXStyle\profile-1.1
Strata: bundled (...\freecad-nxstyle\vendor\freecad-strata)
Katydid: bundled (...\freecad-nxstyle\vendor\Katydid)
SheetMetal: bundled (...\freecad-nxstyle\vendor\FreeCAD_SheetMetal)
LCInterlocking: bundled (...\freecad-nxstyle\vendor\LCInterlocking)
DFM: bundled (...\freecad-nxstyle\vendor\FreeCAD-DFM-Workbench), OCP from ...\FreeCAD-NXStyle\pydeps\py311
----

Open files directly by naming them:

[source,bash]
----
python launch_nx.py part.FCStd
----

[#options]
== Launcher options

[cols="2,5",options="header"]
|===
| Option | What it does

| `--list`
| Lists the FreeCAD installations found, newest first, and exits.

| `--freecad PATH`
| Uses this FreeCAD executable or installation folder instead of the newest one.

| `--profile DIR`
| Uses this folder as the NX profile instead of the default one.

| `--reset-profile`
| Deletes the NX profile before starting, for a clean start.

| `--no-strata`
| Starts without Strata. To switch it off for good, set `"plm": "none"` in the xref:settings.adoc[settings].

| `--no-katydid`
| Starts without Katydid (Algorithmic Modeling). To switch it off for good, set `"algorithmic_modeling": "none"`.

| `--no-sheetmetal`
| Starts without the SheetMetal add-on (Sheet Metal). To switch it off for good, set `"sheet_metal": "none"`.

| `--no-lcinterlocking`
| Starts without the LCInterlocking add-on (Laser Cut). To switch it off for good, set `"laser_cut": "none"`.

| `--no-dfm`
| Starts without the DFM Workbench (Analysis › Molded Part Validation). To switch it off for good, set `"dfm": "none"`.

| `--nxt`
| Starts with the FreeCAD-Nxt add-on, a trial that is off by default (xref:nxt.adoc[]). To switch it on for good, set `"nxt": true`. It needs FreeCAD 1.1 or newer.

| `--import-preferences [GROUPS]`
| Copies preferences from your normal FreeCAD profile, which it only reads: `navigation` (the default), `view_cube`, `macros`, or `all`, comma-separated. To do it at every start, set `"import_preferences"` (xref:settings.adoc#import[]).

| `--user-addons`
| Also loads the add-ons of your normal FreeCAD profile, except those NX-Style bundles or the NX profile already has (xref:#addons[]). To do it at every start, set `"user_addons": true`.

| `--install-dfm-deps`
| Installs what the DFM Workbench needs (cadquery-ocp 7.8.1.1.post1 and VTK 9.3.1, pinned to FreeCAD 1.1's OpenCASCADE 7.8.1, and gmsh 4.15.2 for its colour maps) with FreeCAD's own Python, then exits. The only option that downloads anything.

| `--dry-run`
| Prints the FreeCAD executable, the profile and the command line, and starts nothing.

| `--wait`
| Waits for FreeCAD to exit (useful in scripts).

| `-- ARGS`
| Passes everything after `--` to FreeCAD unchanged.

| `--smoke-test OUTDIR`, `--tutorial OUTDIR`
| Run the self-test or the tutorial replay. See xref:testing.adoc[].

| `--headless-check`
| Loads NX-Style and the add-ons it bundles in this FreeCAD's `freecadcmd` (no window), in a throwaway profile, prints each check and exits 0 only if all of it loads.
|===

[#profile]
== The NX profile

The NX profile is a private set of FreeCAD user folders, one per FreeCAD version:

[cols="1,3",options="header"]
|===
| System | Profile folder

| Windows | `%LOCALAPPDATA%\FreeCAD-NXStyle\profile-<version>`
| Linux | `~/.local/share/freecad-nxstyle/profile-<version>`
| macOS | `~/Library/Application Support/FreeCAD-NXStyle/profile-<version>`
|===

Inside it, `config` holds FreeCAD's `user.cfg` and NX-Style's `nxstyle.json` (see xref:settings.adoc[]), `data` holds the add-ons (`Mod`) and macros, and `temp` FreeCAD's temporary files.

Your normal FreeCAD (`%APPDATA%\FreeCAD` on Windows) is never written, and read only when you ask for its preferences or add-ons (`--import-preferences`, xref:settings.adoc#import[]; `--user-addons`, xref:#addons[below]).
That also means your usual FreeCAD add-ons do not load in the NX profile unless you ask for them (xref:#addons[below]).

[#addons]
=== Your add-ons

Two ways bring a workbench you use into NX-Style:

* Install it in the NX profile with *Tools › Add-on Manager*. It stays there and nothing else changes.
* Load the add-ons of your normal FreeCAD as well: `python launch_nx.py --user-addons` for one start, or `"user_addons": true` in `nxstyle.json` for every start. The launcher loads them from your normal profile's `Mod` folder, which it only reads. It skips an add-on that NX-Style already bundles (Strata, Katydid, SheetMetal, LCInterlocking, the DFM Workbench, FreeCAD-Nxt) and one already in the NX profile, so nothing loads twice. It also skips one you disabled in the Add-on Manager. The start-up lines name what was loaded and what was skipped.

Either way, each workbench appears under *Application › Add-ons* with a ribbon built from its own toolbars.
An add-on that installed Python packages of its own through the Add-on Manager may need them in the NX profile too: install it there once as well.

== Update

[source,bash]
----
git pull
----

[source,bash]
----
git submodule update --init
----

Then start the launcher again. The NX profile is kept; new settings get their defaults.

== Uninstall

. Delete the project folder.
. Delete the NX profile folder (see the table above), or keep it if you might come back.

FreeCAD itself and your normal FreeCAD settings were never changed, so there is nothing else to undo.
