= Testing
:description: The unit tests, the self-test and the tutorial replay: what each checks and how to run it.

Three levels of tests, from seconds to about half an hour.

== Unit tests and lint

[source,bash]
----
python -m unittest discover -s tests
----

[source,bash]
----
ruff check --select F,E9 .
----

The unit tests cover the engineering computations, checked against the books' worked examples: the tolerance stack-up (Fischer's pin and ground plate, Drake's MRSS factor, Cogorno's fastener and boundary formulas), ISO 286 limits and fits (against the ISO 286-1 formulas and published values) and ISO 2768, the PMI semantics (ISO 8015 and ASME Y14.5 checks, inspection plan, gauge sizes), the release package manifest and its verification, the clearance classification, the AP242 mapping of the PMI (and the correction of OpenCASCADE's IT grade), sheet metal bend allowance and flat length (Shih's actuator bracket), pin location (Drake ch. 24, Fischer's lever), composite position frames and the pattern evaluation (its fit checked against a brute-force search), measurement capability (Drake's gauge study example, 42.6 %; TUR and ISO 14253-1 acceptance limits), and the title block values and revision block.
They also cover the launcher: the profile folders and their reset, refusing a profile inside or above the normal FreeCAD folder, the environment and command it builds, which Strata, Katydid, SheetMetal and LCInterlocking it loads and where it reads `nxstyle.json`, that every application's ribbon has the Application tab, that the Laser Cut ribbon names only commands LCInterlocking registers, and the memory ceiling (a runaway is stopped, a second concurrent run refused).
FreeCAD is not needed.
GitHub Actions runs both, and checks that the ribbon files are valid JSON, on every push (Windows and Ubuntu).

== Self-test

[source,bash]
----
python launch_nx.py --smoke-test out
----

This starts FreeCAD with NX-Style in a throwaway profile and drives the real UI with synthetic mouse and key events.
It ends with the count of checks passed, failed and skipped (90 checks on FreeCAD 1.1.4, 2026-10-26). Among them:

* every key in xref:keyboard-shortcuts.adoc[] reaches its command through Qt's real shortcut system, with no other action holding the same key. This checks the dispatch: the test stops the command from then running. Ctrl+Shift+B is pressed for real as the positive control, and a letter key typed into the Command Finder must stay text;
* MB2 rotate, pan and zoom, MB2 click = OK, the MB3 hold radial menu;
* the ribbon, the Type Filter, the Resource Bar and no empty tab strip over the Top Border Bar;
* metric units even when the profile was set to US customary;
* Strata starts and sits with the navigators;
* the Algorithmic Modeling application opens Katydid's canvas, floating, with Canvas, Bake and the Application tab on the ribbon; Canvas is on the Tools tab before Katydid's workbench has started; the selected category tab has a readable label; the canvas stays open after switching back to Modeling;
* the eight PMI model views look as FreeCAD's own standard views do, a new PMI goes into the work view, switching views hides the others' PMI, and Display in Views copies one;
* a plate with PMI written as STEP AP242: datums, the H7 and g6 classes with their right IT grades, position with Ⓜ and flatness in the file, and OpenCASCADE reading back the dimensions and tolerances; the file imported again gives the same PMI;
* a linked part inside a moved assembly is where the assembly puts it for volume claims and clearance, and its hidden source is not counted;
* a composite position frame, its two-row label and the evaluation of a measured pattern; a gauge study on a PMI size; Populate Title Block from part attributes onto an ISO 5457 sheet, with its revision block;
* broken references are reported, not papered over:
** a diameter whose face became a plane is invalid, shows its error, and is kept out of the inspection plan, the stack-up and the STEP export, then valid again when repaired;
** a stack-up whose PMI was deleted gives no result;
** clearance results are out of date after a part moves;
** a pair rule naming a label two parts share is not applied;
* the geometry comparison the tutorials use tells a solid from a different one of the same volume;
* the status bar names NX-Style's mouse handling rather than FreeCAD's Blender base style alone.

A check that needs something this FreeCAD build lacks (pythonocc for AP242, the FEM workbench, QtTest) is counted as *skipped*, never as passed; `--require-all` makes a skipped check fail the run.
It writes `out/smoke.json` and screenshots.

== What the launcher accepts

A result file counts only when it is this run's and the run finished.
The launcher passes each run a new ID, and the result (written atomically by `nxstyle/harness_result.py`) must carry that ID, the schema `nxstyle-harness/1`, status `complete`, and every planned step listed as run.
A tutorial that fails part way lists the steps it then skipped.
So a passing `smoke.json` left in the folder by an earlier run cannot pass a run that crashed, and neither can `{}`, empty lists, a truncated file or a run that stopped half way.
A FreeCAD that exits with an error after writing a good result fails too.
`tests/test_harness_result.py` covers each of these, through `launch_nx.main` with the FreeCAD run replaced by a stub.

== Tutorial replay [[tutorial-replay]]

[source,bash]
----
python launch_nx.py --tutorial out
----

The replay works through the xref:tutorials/index.adoc[tutorials] the way the books tell an NX user to: the same keys, the NX-named ribbon buttons, MB1 clicks on sketch points in the graphics window, MB2 to end tools and accept dialogs.
On the Katydid canvas (tutorials O to R) it double-clicks the empty canvas and types each component's name, drags wires from grip to grip (kbd:[Shift] adds), sets Graft, Flatten and input values from the grips' right-click menu, and types slider values into the slider's dialog; after each step it saves a screenshot with the floating canvas laid over the lower half of the graphics window.
Dimension values are applied through FreeCAD's API, the equivalent of typing them into Rapid Dimension; everything else is real UI input.

Each feature is checked by its volume against the same operation done directly with FreeCAD's Part API.
Volume alone does not prove the shape: a slot cut in the wrong place has the same volume.
Tutorial A therefore also compares the part with a reference solid built with the Part API: their symmetric difference and their bounding boxes must agree (`nxstyle/geomcheck.py`).
The final part must also be drawn in the graphics window. That is an occupancy check (something is drawn), not a check of the image.
Save steps press the real kbd:[Ctrl+S] and check that the file was rewritten; only a new part's first file name is given by script, because the replay cannot drive the system file dialog.
Tutorials S to X check engineering results: the stack-up against Fischer's figures, the fit against ISO 286, the STEP file's PMI and what OpenCASCADE reads back, the inherited dimensions on the sheet, the clearance kinds and penetration depth, the release states in Strata and the release packages against their manifests, the flat pattern against Shih's hand calculation, and the pin location against Drake's formulas.
Dialogs that Strata opens are answered by the replay the way a user fills them in.
Tutorials AA to AC check the composite frame's plan rows and gauges, the evaluation of measured holes, the TUR and acceptance limits, Drake's gauge study result, and the title block against the Strata release.
`--tutorials G,H` picks some; N runs M first, V runs T first, AC runs T and V first.
A run may take 5 minutes plus 5 per tutorial chosen before it counts as timed out; the canvas tutorials O to R take about 20 minutes together.

The replay writes `out/tutorial.json`, a `progress.log` and screenshots.
Exit code 1 means a step FAILED.
The *same*, *differs* and *missing* outcomes are the replay's own judgement of each step against the book; they are not an independently measured equivalence with NX.

== Hidden desktop and memory ceiling

On Windows both runs use a hidden desktop, so nothing appears on your screen; `--visible` shows FreeCAD instead.

Every run is capped at 4 GB of memory (`--max-memory-gb`) inside a Windows job object.
FreeCAD's allocations beyond the ceiling are refused and the run ends with exit code 4, so a runaway cannot take the machine down.
Run one at a time.

[cols="1,3",options="header"]
|===
| Exit code | Means

| 0 | Passed
| 1 | A check or step failed
| 2 | No result: FreeCAD crashed or NX-Style failed to load
| 3 | Timed out
| 4 | Stopped at the memory ceiling
| 5 | Refused to start, for example because another test run is going
| 6 | The result is not this run's, or is incomplete, empty or unreadable
| 7 | FreeCAD exited with an error code
|===

== Testing a second start

Each run uses a fresh throwaway profile.
To test what a second start sees, give both runs the same `--profile DIR`; it is kept between runs.

[source,bash]
----
python launch_nx.py --smoke-test out1 --profile p
----

[source,bash]
----
python launch_nx.py --smoke-test out2 --profile p
----

== From results to the docs

The tutorial pages' step tables come from `docs/results/tutorials.json`: a replay's steps and the FreeCAD version, nothing else.
After a full replay that should be published:

[source,bash]
----
python tools/gen_docs.py --results out/tutorial.json
----

It refuses results that name a folder in your home directory, since they are published.
`python tools/tutorial_table.py out/tutorial.json` prints the result counts per tutorial and updates the table in `docs/TUTORIAL-REPLAY.md`.
See xref:writing-docs.adoc[] for building the site.
